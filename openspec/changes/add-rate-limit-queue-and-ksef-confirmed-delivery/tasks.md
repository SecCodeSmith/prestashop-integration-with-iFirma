# Tasks

Conventions for every task:
- TDD per CLAUDE.md. Write the failing test first and record its failure output in the task's commit message or the apply log. Then the simplest code that passes, then a refactor with the suite green. A test whose expectation changes deliberately (named in design.md D3 and D8) changes in its own commit, which explains why.
- Module unit suite: `composer test` (PHPUnit 9.6, `phpunit.xml.dist`), from the scratchpad PHP toolchain or inside the PrestaShop container as `www-data`. Coverage: `composer coverage`, then the diff-cover gate on `build/coverage.xml`. Every changed line must be covered before group 9 closes.
- Group 1 changes only the `test-stack` submodule (its own MIT repository). The mock's pytest suite (`test-stack/ifirma-mock/.venv/Scripts/python.exe -m pytest -p no:warnings`) must pass after every task in that group, and every new `.py` file carries the mock's MIT header (`python test-stack/tools/check_license_headers.py`).
- Docker runs only inside WSL (`wsl.exe -e bash -lc '...'`). The two local stacks are `ifirma-test-stack` (PS 8.1, `build/tools/local.yml`) and `ifirma-ps91` (PS 9.1, `build/tools/local91.yml`). Rebuild the mock with `docker compose -p <project> -f docker-compose.yml -f ../build/tools/<override> up -d --build --no-deps ifirma-mock`. Never run `make up` or `make destroy` on these long-running stacks.
- Settings go through `IfirmaSettings`. New keys also go into `IfirmaSchema::configurationDefaults()`, so `tests/Unit/ConfigurationKeysTest.php` covers install and uninstall.
- No secrets in tests, fixtures, docs or commits. Use placeholders only.
- Work split per design D12: group 1 runs alongside groups 2 to 3. Group 4 needs group 2's `rateLimitWindow()` and group 3's back-off. Group 5 needs group 4. Group 6 needs 5.1's job interface. Group 7 needs the record states from 4.1 and the gate from 6.5. Group 8 needs everything before it. The manager verifies and commits per group, one concern per commit.
- Run `graphify update .` from the repo root after each group's code lands.

Design decisions are referenced as D1 to D12 (design.md). Scenarios are referenced by name from the delta specs under `specs/`.
