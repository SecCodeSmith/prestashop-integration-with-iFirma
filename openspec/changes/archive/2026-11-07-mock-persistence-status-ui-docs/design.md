# Design

## Context

See proposal.md - Why. Facts that shape the approach (read in this planning pass):

- **Mock state today.** `test-stack/ifirma-mock/app/store.py` keeps module-level dicts (`_documents`, `_contractors`), two `itertools.count` sequences, three test switches and one `threading.Lock`. `main.py` keeps the call accounting (`_calls`, `_register_call()`, `reset_counters()`) and mutates documents directly in four places outside the store (`ksef_send` sets `ksef_status`, `send_document` sets `sent`, `mock_ksef_accept`/`mock_ksef_reject` set `ksef_status`/`ksef_number`). `POST /__mock/reset` calls four reset functions. `GET /` answers JSON (service, version, user, base URL, strict auth, document count); `/health` feeds the Docker healthcheck. Every `/__mock/*` route starts with `_test_endpoints_disabled()`.
- **Tests.** Six pytest modules use a module-level `TestClient(app)` (no `with`, so FastAPI startup/lifespan never runs) and `autouse` fixtures that call `POST /__mock/reset` before and after each test. The suite runs in the test-stack CI and in the parent CI `mock` job (`.github/workflows/ci.yml`, `submodules: true`). New `.py` files need the MIT header checked by `test-stack/tools/check_license_headers.py`.
- **Container.** `Dockerfile` copies `app/` (no bind mount, no volume); `docker-compose.yml` has services `db`, `ifirma-mock` (port 8001, env `IFIRMA_MOCK_*`) and `prestashop` (module bind-mounted); the `Makefile` has `up`, `down`, `destroy` (`down -v`), `logs`, `test`. Locally two stacks run from the same files with git-ignored overrides (`build/tools/local.yml` on 8099 and `local91.yml` on 8091, compose projects `ifirma-test-stack` and `ifirma-ps91`); after a mock change both mocks need `up -d --build --no-deps ifirma-mock`.
- **Two repositories.** `test-stack/` is a submodule of the public repository `SecCodeSmith/test-stack` (MIT). Changes to the mock are commits there; this repository then bumps the pointer (precedent: archived change `2026-11-04-ci-test-builds-and-housekeeping`, D6).
- **Documentation.** `README.md` is 745 lines in 20 sections with no image; there is no `docs/` folder; `build/` (where the earlier back-office screenshots sit) is git-ignored; `package.json` `files` and `scripts/build-zip.mjs` allow-list the shipped paths (README.md yes, `docs/` and `tools/` no). The README inventory made for this change found no dead file or class reference, three statements of the rate limits, the configuration keys split over five places, a pipeline list without the `ksef` step, and troubleshooting text bound to build dates and to "version 1.1.0".
- **Screenshots.** A headless recipe exists from the previous change: `puppeteer-core` driving the installed Chrome (`C:/Program Files/Google/Chrome/Application/chrome.exe`) against the PS 8.1 back office on `http://localhost:8099/admin-dev/` (`admin@example.com` / `Passw0rd!`), reusing a `_token` from any back-office link.
- **Module facts for the architecture page** (from the inventory): `ifirma.php` registers nine hooks (`displayAdminOrderMainBottom`, `displayAdminCustomers`, `displayCustomerAccount`, `displayOrderDetail`, `actionOrderStatusPostUpdate`, `header`, three `actionOrderGrid*Modifier`), three front controllers (`receipt`, `datarequest`, `cron`) and one admin controller (`AdminIfirma`, AJAX actions); 46 classes under `classes/` with `IfirmaIssuancePipeline` (steps hold, guard, create, number, ksef, deliver) and `IfirmaReceiptService` as the centre; three tables (`ifirma_receipt`, `ifirma_data_request`, `ifirma_contractor_map`) defined in `IfirmaSchema`; upgrade scripts 1.1.0, 1.2.0, 1.4.0; configuration keys grouped as connection, document, triggers, delivery, KSeF, duplicate guard, status/cron, rate limiting.

## Goals / Non-Goals

**Goals:**

- One owner of all mutable mock state, so "write after every change" and "reset clears everything" are each one call, and the pytest suite keeps running memory-only without any test edit.
- A status page that is one Python module with no new dependency, whose actions share the implementation of the existing JSON helpers instead of duplicating it.
- A README a shop owner can read in a few minutes, with the detail moved verbatim into pages that keep their headings, so nothing documented is lost and old anchors still find their section.
- Screenshots that can be regenerated by a script, not by hand.
- Work split so several agents can build in parallel without editing the same file.

**Non-Goals:**

- Persisting the per-minute rate-limit window (it is meaningless after a restart).
- A database, multi-process safety or concurrent writers for the mock state (one uvicorn worker, one file).
- Authentication for the status page beyond the existing test-endpoint gate (the mock is a local test double).
- Changing any `/iapi/*` response, the module's PHP code, its payloads or its package layout.
- Translating the documentation or the status page into Polish.

## Decisions

### D1. The store owns every piece of mutable state and announces changes

`store.py` becomes the single owner: the call counters move in from `main.py` (`register_call()`, `calls_total()`, `calls_this_minute()`), the four direct document mutations in `main.py` become store functions (`set_ksef_status(doc_id, status, number=None)`, `mark_sent(doc_id, recipient)`), the two `itertools.count` sequences become plain integers under the lock (`_next_document_id`, `_next_contractor_seq`) so they can be saved and restored, and one `reset_all()` replaces the four resets. Every mutating function ends, still under the lock, with `_changed()`, which calls the listener registered through `store.on_change(callback)` (none by default). `snapshot()` returns a plain dict (documents through `dataclasses.asdict`, contractors, both next values, the three switches, `calls_total`); `restore(snapshot)` replaces the state and tolerates missing or unknown document keys (missing keys take the dataclass defaults, unknown keys are dropped) so an older or newer file still loads.

*Alternative:* wrap each public function with a decorator that persists after the call. Rejected: the mutations in `main.py` would stay invisible, and the lock would be released between the change and the write.

*Alternative:* leave the counters in `main.py` and snapshot them separately. Rejected: two owners for one reset and one snapshot, which is exactly the state of affairs that makes "reset" forget things.

### D2. One JSON file, versioned, written atomically, loaded tolerantly

New `state.py`: `start(settings)` runs at application start, `persist(snapshot)` is the store listener, `info()` feeds the status page. The file is UTF-8 JSON:

```json
{"version": 1, "saved_at": "2026-11-07T10:00:00+00:00",
 "next_document_id": 3, "next_contractor_seq": 2,
 "documents": [...], "contractors": {"K000001": {...}},
 "switches": {"contractor_create_mode": "normal", "pdf_not_ready_remaining": 0, "legacy_mode": false},
 "calls_total": 17}
```

`persist()` writes `<file>.tmp` and `os.replace()`s it over the file, so a crash leaves either the old or the new file; an `OSError` is logged (logger `ifirma-mock`, visible in `uvicorn` output and `make mock-logs`) and swallowed, so the request still gets its answer. `start()` reads the file; invalid JSON or `version != 1` renames it to `<file>.corrupt-<YYYYmmddHHMMSS>` and starts empty with a warning; a missing file starts empty silently; a readable file is passed to `store.restore()`. The write happens inside the store lock (the listener is called under it): the file is a few hundred kilobytes at most and the mock serves one request at a time anyway.

*Alternative:* SQLite. Rejected: more code for the same guarantees, and the file stops being readable and editable by hand, which is the point of a test double.

*Alternative:* write on shutdown only. Rejected: a killed container (the normal way Docker stops things) would lose the session, and the clean/reset semantics would depend on a graceful stop.

### D3. Settings and start-up: memory-only by default, file in the stack, clean start as a start-up flag

Two settings in `config.py`: `state_file` (`IFIRMA_MOCK_STATE_FILE`, default empty = memory only) and `clean_start` (`IFIRMA_MOCK_CLEAN_START`, default false). `main.py` gets a FastAPI lifespan handler that calls `state.start(settings)`: with an empty path it does nothing (today's behaviour, and what the pytest suite sees because its module-level `TestClient` never runs the lifespan); with a path it first deletes the file when `clean_start` is on (logged), then loads, registers `store.on_change(state.persist)` and persists once, so the file reflects the state the mock actually started with (empty after a clean start). `POST /__mock/reset` becomes `store.reset_all()`, which fires the listener and rewrites the file empty.

In the stack: `docker-compose.yml` adds the named volume `mock_data` mounted at `/data`, sets `IFIRMA_MOCK_STATE_FILE=/data/ifirma-mock-state.json` and `IFIRMA_MOCK_CLEAN_START: ${IFIRMA_MOCK_CLEAN_START:-false}`; the `Dockerfile` creates `/data`; the `Makefile` gets `up-clean` = `IFIRMA_MOCK_CLEAN_START=true docker compose up -d --build --force-recreate --no-deps ifirma-mock`. Because the variable is baked into the container, a later `docker compose restart ifirma-mock` would start clean again; `make up` (or any `up` without the variable) recreates the container with `false` and the state is kept from then on. The README of the stack says this in one sentence next to the target.

*Alternative:* a one-shot `docker compose run --rm ifirma-mock python -m app.state --clean` that wipes the volume while the service is stopped. Rejected: three commands and a stop/start dance for the same result; the user asked for an argument on the run.

*Alternative:* a compose profile or a second service. Rejected: more moving parts than a variable.

### D4. Status page: one rendering module, routes that reuse the JSON helpers, redirect after every action

New `ui.py` renders the page from a plain dict with `html.escape` on every value and a small inline stylesheet; no template engine, no JavaScript apart from `onclick="return confirm(...)"` on the reset and delete buttons. `main.py` gains `status_data()` (settings, `state.info()`, counters, switches, documents newest first as `_row()` plus `deleted`, `created_by` and `statuses`, contractors) and the routes:

| Route | Does |
|-------|------|
| `GET /__mock/status` | HTML page (`ui.render(status_data(), flash)`), flash text from `?msg=`/`?error=` |
| `GET /__mock/status.json` | `status_data()` as JSON |
| `POST /__mock/ui/seed` | form: `doc_type`, `name`, `identifier`, `nip`, `email`, `gross`, `paid` → same helper as `POST /__mock/documents` |
| `POST /__mock/ui/switch/{contractor-mode\|pdf-not-ready\|legacy-mode}` | form field `value` → same helpers as the JSON switch routes |
| `POST /__mock/ui/documents/{id}/{ksef-accept\|ksef-reject\|delete}` | same helpers as the KSeF and delete routes |
| `POST /__mock/ui/reset` | `store.reset_all()` |

Every `POST` answers `303 See Other` to `/__mock/status?msg=…` (or `?error=…` for a bad amount or an unknown id), so a browser refresh never repeats an action. To share the implementation, the bodies of `mock_seed_document`, `mock_ksef_accept`/`reject`, `mock_delete_document` and the three switch setters are lifted into plain functions (`seed_document(body) -> row`, `ksef_outcome(doc_id, accepted) -> row | None`, ...) that both the JSON routes and the form routes call; the JSON routes keep their exact answers (the existing tests prove it). All new routes start with `_test_endpoints_disabled()` and none calls `register_call()`, so the page never counts as API traffic. `GET /` keeps its keys and adds `"status_page": "/__mock/status"`.

*Alternative:* serve the page at `/` for browsers (content negotiation) or redirect `/` to it. Rejected: `/` is read by scripts as JSON today and a conditional answer is a surprise; a link in the JSON is enough.

*Alternative:* Jinja2 templates. Rejected: a dependency and a folder for one page; the page is tables and forms.

### D5. Screenshots: four fixed file names, one script, taken on the PS 8.1 shop

File names are fixed now so the documentation pages can reference them before the images exist: `docs/img/mock-status.png`, `docs/img/bo-order-panel.png`, `docs/img/bo-orders-list.png`, `docs/img/module-configuration.png`; the status-page image is also committed as `test-stack/docs/img/mock-status.png` so the standalone mock repository's README has it. `tools/screenshots.mjs` (Node ESM, `puppeteer-core`, installed ad hoc with `npm i --no-save puppeteer-core` so `package.json` and the CI installs do not change) reads `CHROME_PATH`, `PS_URL` (default `http://localhost:8099`), `PS_ADMIN_DIR` (`admin-dev`), `PS_ADMIN_MAIL`, `PS_ADMIN_PASSWD`, `MOCK_URL` (default `http://localhost:8001`) and `OUT_DIR` (`docs/img`), seeds two documents on the mock (one paid, one with a KSeF acceptance) so the status page is not empty, logs into the back office, and shoots: the status page (full page, 1280 px wide), the module configuration page, the Orders list (viewport, with the iFirma column visible) and an order page clipped to the module panel card. Images are PNG at device scale 1 and must stay under 300 KB each (the earlier 1280-px back-office shots were 120-185 KB). The script lives under `tools/` (outside the package allow-list) and follows the comment-header style of `scripts/build-zip.mjs`.

*Alternative:* commit the earlier `build/shots/*.png`. Rejected: they show the customer page and an orders list from before this change, were taken for a measurement, and nobody can regenerate them.

## Risks / Trade-offs

- [Writing the file under the store lock slows every mutation] → Only when a file is configured (never in pytest); the file is small and the mock serves one request at a time. If the smoke run gets measurably slower, the write can be moved to a debounced background thread without changing the contract.
- [The clean-start variable sticks to the container] → `make up` recreates without it; the Makefile and the mock README say so; `docker compose config` shows the effective value.
- [The two local stacks start empty after the rebuild] → Same as every restart today; the status page and its seed form make the one-time reseed a click. The smoke run still ends with `/__mock/reset`, so it keeps leaving an empty mock as before.
- [`main.py` edited by two agents] → Regions are disjoint (lifespan/reset versus the status block at the end of the file); the lead merges and runs the whole pytest suite before pushing.
- [Parent CI red between the test-stack push and the pointer bump] → The order is fixed: push the submodule first, then bump; the parent's `mock` job runs the new tests on the pinned commit.
- [README restructure breaks an inbound link] → No file in the repository links to a README anchor (checked); headings keep their text inside the new pages, and the README's documentation table names every page.
- [Screenshots show test credentials] → Only the documented mock login and key (`test@example.com`, the all-ones key) and `admin@example.com`; nothing secret. The script must not be pointed at a real shop.
- [A corrupt state file hides a bug] → The file is kept aside with a timestamp, never deleted, and the warning names it.

## Migration Plan

1. Land groups A-C in the `test-stack` repository (mock version 1.1.0), push, confirm its CI (pytest and licence check) is green.
2. Rebuild the mock in both local stacks (`docker compose -p <project> -f docker-compose.yml -f <override> up -d --build --no-deps ifirma-mock`); the new volume starts empty; seed once from the status page; confirm a `restart` keeps the documents.
3. Take the screenshots (group F), land groups D-F and the submodule bump in this repository, run the link check, `npm run verify:package` and `graphify update .`, confirm the parent CI is green (GitHub API, no `gh` here).
4. Rollback: revert the commits in this repository (the old pointer brings back the old mock), then in `test-stack`. An old mock ignores the volume and the two new variables; a new mock without `IFIRMA_MOCK_STATE_FILE` behaves like the old one.
