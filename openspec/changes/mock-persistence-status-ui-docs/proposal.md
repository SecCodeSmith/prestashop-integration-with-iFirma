# Proposal

## Why

The mock iFirma API of the test stack keeps everything in memory and "resets on restart" (`test-stack/ifirma-mock/app/store.py`). The mock has no bind mount, so every edit means `docker compose up -d --build --no-deps ifirma-mock`, and every rebuild, Docker restart or host reboot wipes the documents and contractors the two Docker shops reference: the module then answers Kod 404 for every PDF, the order panels show documents the mock no longer knows, and each smoke run has to reseed by hand (see `/__mock/reset` + `/__mock/documents` in the smoke notes). There is also no way to see what the mock holds, which switches are on or how many calls it served without typing `curl` commands against JSON endpoints.

On the documentation side, `README.md` has grown to 745 lines that mix shop-owner, integrator and maintainer material: the configuration keys and the rate limits are described three times, the troubleshooting section is stamped with build dates from 2026-11-02 and a "version 1.1.0" check, the issuance pipeline list omits the `ksef` step that the KSeF section adds, there is not a single screenshot, and nothing explains how the classes, hooks, tables and the test stack fit together. A reader (or an agent) has to read code to learn the architecture.

The official iFirma API documentation (<https://api.ifirma.pl/>: authorization header, `fakturakraj`/`fakturaparagon`, `faktury.json`, `kontrahenci`, KSeF send, `abonent/limit`, FAQ error codes) was re-read for this change. The mock already mirrors the documented endpoint family, envelope and HMAC-SHA1 scheme, so this change does not touch the API contract; it makes the mock a durable, inspectable test double and gives the project a navigable documentation set.

## What Changes

- **The mock remembers its state across restarts.** Documents, contractors, their identifier sequences, the test switches (contractor mode, PDF-not-ready counter, legacy mode) and the served-call counter are written to a JSON state file after every change and loaded when the mock starts. In the compose stack the file lives on a named Docker volume, so `docker compose up -d --build`, `restart` and host reboots keep the documents the shops reference. Without a configured state file the mock behaves exactly as today (memory only), so the pytest suite and ad-hoc `uvicorn` runs are unchanged. `POST /__mock/reset` clears the persisted state as well as the memory.
- **A clean-start argument.** `IFIRMA_MOCK_CLEAN_START=true` makes the mock discard the stored state when it starts (`IFIRMA_MOCK_CLEAN_START=true docker compose up -d --force-recreate ifirma-mock`, wrapped as `make up-clean`); `make up` brings the stack up with the stored state. The variable is read at start-up only; the stack files and the mock README spell out that a recreated container keeps whatever value it was created with.
- **A status page for the mock.** `GET /__mock/status` renders a plain HTML page (no JavaScript framework, no new dependency): a menu of links (Swagger `/docs`, `/health`, the JSON twin `GET /__mock/status.json`, the mock README), the effective settings and the persistence state (file, last write, clean start), the call counters, the three test switches with toggle forms, the stored documents (newest first, with the fields of the `faktury.json` row and per-row KSeF accept/reject and delete actions) and the stored contractors. A small form seeds a sample receipt or invoice (contractor, gross, paid, document type) through the existing seeding logic, so a document can be created without `curl`. A reset button wipes everything. The page and its forms are test-only like every `/__mock/*` route: HTTP 404 when `IFIRMA_MOCK_TEST_ENDPOINTS=false`. `GET /` keeps its JSON and gains the link to the page.
- **Screenshots.** `docs/img/` gets the mock status page, the back-office order panel of the module, the Orders list with the iFirma column and the module configuration page, taken headlessly on the PrestaShop 8.1 test shop. A small re-runnable script (`tools/screenshots.mjs`, puppeteer-core against the installed Chrome, outside the module package) documents how they were taken so they can be refreshed.
- **README cleanup.** `README.md` becomes the entry page: what the module does, requirements and compatibility, installation with the minimum settings, a short "how it is used" with the screenshots, the links to the documentation pages, the legal notice. Everything else moves verbatim into `docs/` pages (`configuration.md`, `usage.md`, `contractors.md`, `upgrading.md`, `development.md`, `troubleshooting.md`), with these corrections while moving: the configuration keys and the rate limits are stated once, the two "Usage flow" headings are renamed so they no longer clash, the pipeline step list gets its `ksef` step, the dated troubleshooting notes ("builds from 2026-11-02 19:30 onward", "confirm the module version is 1.1.0") become version-neutral, and Kod 208 joins the error-code table. No documented fact is dropped.
- **Architecture documentation.** New `docs/architecture.md` describes the module (entry points and hooks, the class layers, the issuance pipeline, the data model and configuration keys, the request flow of "Create Receipt") and the test stack (compose services, mock internals, signing, persistence, status page), with Mermaid diagrams GitHub renders. `test-stack/README.md` documents the state file, the clean-start argument and the status page.
- **Mock version** moves from 1.0.0 to 1.1.0 (`pyproject.toml`, FastAPI title) because it gains features.
- **Unchanged:** the module's PHP code, its iFirma payloads and API calls, its database schema, the package allow-list (`docs/`, `tools/` and `test-stack/` stay outside the zip as today) and the mock's `/iapi/*` contract.

## Capabilities

### New Capabilities

- `mock-state-persistence`: how the mock iFirma API keeps its documents, contractors, counters and switches across restarts: what is persisted, when it is written and loaded, the memory-only mode, the clean-start argument and what `/__mock/reset` clears.
- `mock-status-page`: the test-only status page of the mock: what it shows, which actions it offers (seed a sample document, KSeF outcome, delete, switches, reset), its JSON twin, and that it is gated like the other test endpoints.

### Modified Capabilities

- none. The module's behaviour, its API usage and the package layout do not change, so `module-packaging` and `ifirma-api-compliance` keep their requirements. The README restructure and the new documentation pages are tracked in tasks.md.

## Impact

- **test-stack submodule (its own repository, MIT):** `ifirma-mock/app/store.py` (state snapshot and restore, call counter), new `ifirma-mock/app/state.py` (file read/write, clean start) and `ifirma-mock/app/ui.py` (status page rendering), `ifirma-mock/app/main.py` (status routes, form actions, reset writes the file, `/` link), `ifirma-mock/app/config.py` (two settings), `ifirma-mock/Dockerfile` (state directory), `docker-compose.yml` (named volume, two variables), `Makefile` (`up-clean`), `.env.example`, `ifirma-mock/pyproject.toml`, `README.md`; new pytest modules for persistence and the status page. Every new `.py` file carries the mock's MIT header (`tools/check_license_headers.py` of the submodule).
- **Module repository:** `README.md` (slimmed), new `docs/*.md` pages and `docs/img/*.png`, new `tools/screenshots.mjs`, the submodule pointer `test-stack` bumped to the pushed mock commit, `graphify-out/` rebuilt. No PHP, SQL, template or translation change, so the PHPUnit suite, the licence check of the module and the package build are unaffected; `docs/` and `tools/` are already outside the package allow-list of `package.json`/`scripts/build-zip.mjs`.
- **Two-repository workflow:** the mock changes are committed and pushed in `test-stack` first (CI of that repository runs pytest and the licence check), then the pointer is bumped here; the parent CI `mock` job checks the submodule out and runs the same pytest suite, so the new tests gate both repositories.
- **Running stacks:** the first `up` after the change creates the volume empty; the shops' existing module records then point at documents the mock does not know until they are reseeded once (same as after any restart today). From then on restarts keep the state.
- **Multi-agent implementation:** the work splits into independent file-ownership groups (persistence, status page, stack files, README split, architecture page, screenshots) that can be built in parallel and integrated by one lead; tasks.md states the ownership and the order.
- **Assumptions recorded for review:** "simple receipt gen with some memory" is read as the mock seeding and remembering documents (status-page form plus the persisted state), not as a change to the module's own document type (`fakturaparagon` stays disabled in `IfirmaDocumentSettings`); "the arg to run container with clean start" is read as a compose/Make argument that the mock honours at start-up; screenshots are taken on the PrestaShop 8.1 shop of the running stack with the English back office; the documentation stays in English and links to `docs/` relatively (GitHub renders them), while the shipped zip keeps only `README.md`.
