# Tasks

Conventions for every task:
- Groups 1-3 change the `test-stack` submodule (its own public MIT repository): commit there first and push before the pointer is bumped here (group 5). Every new `.py` file carries the mock's MIT header; `python test-stack/tools/check_license_headers.py` must pass.
- The mock's pytest suite (`test-stack/ifirma-mock/.venv/Scripts/python.exe -m pytest -p no:warnings`, no extra `-q`) must pass after every group that touches the mock; the existing tests must pass unchanged.
- Groups 4-6 change only `tests/smoke/`, docs and the submodule pointer in this repository: no PHP under `classes/`, `controllers/` or `ifirma.php`, no templates, no translations, so no PHPUnit, coverage gate or translation work is owed; `php -l` on the edited smoke script must pass (run in the container as `www-data`).
- Docker runs only inside WSL (`wsl.exe -e bash -lc '...'`); bring the mock up per stack with `docker compose -p <project> -f docker-compose.yml -f ../build/tools/<override> up -d --build --no-deps ifirma-mock` (`ifirma-test-stack` + `local.yml`, `ifirma-ps91` + `local91.yml`); never `make up` or `make destroy` on the long-running stacks.
- Run `graphify update .` from the repo root, alone, after the code changes land (CLAUDE.md).
- Work split per design D8: groups 1 and 2 can run together (store function names fixed in D2, routes in D3), group 3 alongside them, group 4 after D2/D3 names are final (verification needs the rebuilt mocks), group 5 is the lead's integration run, group 6 after 5.

Design decisions are referenced as D1-D8 (design.md); scenarios by name from `specs/mock-smtp-sink/spec.md`, `specs/email-e2e-verification/spec.md` and `specs/mock-status-page/spec.md`.
