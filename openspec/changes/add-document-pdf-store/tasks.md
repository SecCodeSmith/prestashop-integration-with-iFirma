# Tasks

Rules for every group (CLAUDE.md): test first and show the red run before the code; one concern per commit; no test, check or scenario is deleted, skipped or weakened; a golden fixture changes only with a deliberate behaviour change that the commit explains; no version string is edited by hand; the unit suite runs with `composer test` from the scratchpad PHP toolchain or the test-stack container; each step appends one line to `build/progress.log`.

## Pull requests

One pull request per task group (CLAUDE.md, "Pull requests"), stacked in the order below. Each branch starts from the previous one, the first from `feat/api-usage-delivery-retry-status-filter` (pull request #3) until that is merged. Every slice is green on its own (suite, changed-line coverage, its docs). Nothing stores or serves a copy before slice 5, and the deletion paths (slice 4) land before that. At most three slices are open at a time.

| # | Branch | Task group | What it adds | Reachable after the merge |
|---|--------|------------|--------------|---------------------------|
| 0 | `docs/pdf-store-plan` | none | proposal, design, specs and tasks of this change | docs only |
| 1 | `feat/pdf-store-1-storage` | 2 | table, value object, store; the upgrade creates the table | no caller |
| 2 | `feat/pdf-store-2-lifetime` | 3 | setting "Keep PDF copies (days)", retention, saving 0 deletes the copies | the setting is visible; nothing is stored yet |
| 3 | `feat/pdf-store-3-service` | 4 | fingerprint and the service that owns the copy and the fetch | no caller |
| 4 | `feat/pdf-store-4-deletion` | 8 | purge cron job, customer-delete hook, the upgrade registers the hook | the purge runs on an empty table |

| 7 | `feat/pdf-store-7-delivery-mail` | 7 | the delivery e-mail stores the copy | yes |

Group 1 (archive order) and group 9 (integration checks on the tip of slice 7) are not pull requests; the `fix-vuln` commits of 9.4 get their own.
